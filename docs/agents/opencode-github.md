# OpenCode в GitHub Actions

Правила для запусков `anomalyco/opencode/github` в этом репозитории. Они дополняют `AGENTS.md` и не заменяют описания навыков.

## Контекст Issue и Pull Request

Заголовок, тело, автор, дата, состояние и комментарии Issue/PR уже передаются в промпте. Для задач «объясни», «проанализируй», triage и подобных используйте этот контекст и файлы checkout.

Не проверяйте переменные окружения, не ищите токены и не вызывайте `gh` только для того, чтобы получить данные, которые уже есть в промпте. Если меток или другого поля нет в переданном контексте, явно отметьте это в ответе, но не переходите к поиску учётных данных.

## Файлы и секреты

Работайте с файлами внутри checkout. Не читайте `$HOME`, `~/.config`, `~/.gitconfig`, SSH-ключи и другие пути вне репозитория: `opencode.json` запрещает такой доступ, а в GitHub Actions некому ответить на интерактивный запрос разрешения.

Файлы `.env` и `.env.*` тоже запрещены к чтению. `.env.example` можно читать как безопасный пример. Ни в ответе, ни в комментариях не приводите значения ключей и токенов.

## GitHub CLI

`gh` не запрещён глобально. Используйте его только тогда, когда задача явно требует работы с GitHub Issues или Pull Requests и у текущего запуска есть необходимые разрешения — например, в сценариях `to-spec`, `to-tickets` и `implement-spec`.

Для обычного объяснения или анализа достаточно данных из промпта и репозитория; дополнительные вызовы `gh` в таком случае являются лишней работой.

## Режим доступа

По умолчанию используется primary-агент `readonly`: он может читать файлы и инструменты поиска, но не может редактировать файлы (`edit`), выполнять shell-команды (`bash`), запускать подзадачи (`task`) или обращаться к сети. Это важно, потому что официальный экшн для Issue автоматически коммитит любое изменение в рабочем дереве, пушит новую ветку и открывает PR.

Агент `build` с правом на изменения выбирается только при явной просьбе запустить `to-spec`, `to-tickets` или `implement-spec` (например, `запусти implement-spec`, `/oc implement-spec`, `/implement-spec`). Упоминание навыка в запрете (`implement-spec не запускай`) write-режимом не считается: комментарии с отрицанием остаются read-only.

Workflow проверяет чистое рабочее дерево до запуска агента. После read-only запуска проверка повторяется; если файлы всё же изменились, job завершается ошибкой.

## Неинтерактивный режим

Запросы к пользователю (`question`) запрещены: если данных не хватает, включите уточняющие вопросы в итоговый ответ, но не ждите ответа в середине запуска.

Если инструмент заблокирован конфигурацией, продолжайте с доступной информацией и сообщите об ограничении в ответе. Не повторяйте заблокированный вызов и не пытайтесь обойти запрет через другие инструменты. Для задач «объясни/проанализируй» не меняйте файлы, не создавайте ветки, коммиты и Pull Requests, если это явно не требуется задачей.
